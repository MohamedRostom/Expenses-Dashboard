# Branch review: `phase-1/accounts` (e9e8cc0..9601249)

**Date:** 2026-09-19 · **Scope:** the whole branch against `main` (286 files, ~21k lines) · **Method:** three independent read-through reviews split by area (API/db/contracts; web/ui/landing; core/connectors/tests/infra/CI), each in passes, then the headline findings were re-verified by hand in this checkout. Local Vitest suites, typecheck and `core` coverage (96 %) were run; the Testcontainers API suite, compose e2e-ci and Lighthouse were not (no Docker on the review machine), so anything about those is from reading.

**Verdict: not ready to merge as one branch.** The foundations are good — Argon2id via `hash-wasm`, hashed sessions with `__Host-` cookies, AES-GCM secret box, a real 11-route ownership matrix, BigInt half-even money maths, SQL migrations under an advisory lock, a generated OpenAPI with a staleness check, a correctly gated e2e-local workflow and a clean CI skeleton. But a set of features the CHANGELOG lists as built do not work end to end, and the green unit suites are not evidence for them because the failures sit at integration boundaries (a real browser, real Notion, a running scheduler, a real PR). Fix the fourteen Critical items below, then split into phase PRs and let CI run for real.

## Cross-cutting themes

Four patterns explain most of the Critical list, and each is one fix that clears several findings:

1. **Stubs that were never revisited.** `grep -rn "doesn't exist yet\|don't exist yet"` finds five comments from Phase 1 that still gate real code: GDPR export returns `[]`, housekeeping never purges, the rates retry job is a no-op, seed `--load` is a stub, currency-change ignores expenses.
2. **Nothing runs background jobs.** `registerAllJobs` has no production caller, `tick.ts` throws, `node.ts` has no in-process tick, the distroless image has no shell or pnpm for the documented `flyctl ssh console` approach, and no workflow schedules anything. Currency change, Notion sync, rates warm, housekeeping and the feedback digest therefore never execute anywhere.
3. **Fakes validated against guessed fixtures.** The Notion client sends `2025-09-03` in the header but pre-2025 shapes in the bodies; the fixtures, `FakeNotion` and `infra/mocks` all mirror the same wrong shapes, so contract tests pass while real Notion returns 400.
4. **Browser-only failures.** `<Toast />` is never mounted, `<input type=number>` has no `step` so `4.50` cannot be submitted, the service worker's `navigateFallback` swallows the OAuth redirects, the offline queue drops rows on 401 and the app renders blank when opened offline. jsdom cannot see any of these; only the Playwright `ci` project would — and it has never run (see C11).

## Important (fix before calling the phase done)

**Security and correctness (api).** Per-IP rate limits read the client-controlled first `X-Forwarded-For` entry (`auth.ts:49`, `feedback.ts:69`) — use `Fly-Client-IP`/`CF-Connecting-IP`, fall back to the last XFF entry. Login never checks `emailVerifiedAt` (FR-001) and housekeeping will delete the unverified user's data at day 7. `categoryId` in create/patch expense, import fixes and capture mapping is only uuid-validated, so user A can attach user B's category id — validate ownership in the services (or a composite FK `(user_id, category_id)`) and add body-id rows to the ownership matrix. The job claim (`runner.ts:30-39`) is `FOR UPDATE SKIP LOCKED` outside a transaction and never sets `running`, so two tickers run the same job — claim with `UPDATE … WHERE id IN (SELECT … FOR UPDATE SKIP LOCKED) RETURNING *`. Email change has no re-auth when a password exists, no uniqueness check and no rate limit. The capture webhook writes an audit row per unknown token (storage exhaustion on a public path) and inserts the receipt after the expense (duplicate on concurrent delivery) — insert the receipt first with a pre-generated id. HIBP fail-open only handles `!res.ok`; a thrown `fetch` 500s registration — try/catch plus `AbortSignal.timeout`. Unknown errors are reported as `validation_failed` (`errors.ts:122`) and Sentry gets a synthetic error without the stack — add an `internal` code and pass the real exception. The feedback digest interpolates user text into HTML unescaped. Bare-string dates, unchecked `:id` params, non-decimal `rate` strings and unknown currency codes reach Postgres or core and become 500s — a `validation.test.ts` that throws garbage at every route and asserts 400 would catch the lot. Emails are not lower-cased, so `Foo@x` and `foo@x` are two accounts.

**Data flow (api).** Notion→Desk edits update `amount_original` without recomputing `amount_default` and ignore the category (`notion.ts:422-435`) — route through `expensesService.patch`. The rates cache misses every non-trading day because the lookup is by exact date while the provider caches the previous published date — also accept `rate_date <= date` within 7 days. Import dedupe compares external ids against internal UUIDs (`imports.ts:209`) — read `import_rows.external_id`; commit is neither transactional nor resumable. Sessions are created without `userAgent`/`ip`, so the sessions list is always blank. Notion OAuth registers `${appOrigin}/auth/notion/callback` but the handler is at `/notion/callback` and nothing serves the registered path. Summary endpoints select every expense the user owns and filter in JS; entries paginate by random v4 id (schema says v7) — add date predicates and `ORDER BY expense_date DESC, id DESC`.

**Core.** A full reconcile (`cursor === null`) marks every matched row a conflict without comparing content, writing two `sync_conflict` versions per expense on every first sync. `convert` throws `RangeError` when the result rounds to zero (1 JPY on a GBP account → 500) — return the zero and keep the non-zero invariant in `Money()` for user input only.

**Web.** No sign-out anywhere (`session.logout()` has no caller). The saved theme is applied only when visiting Settings. `/import`, `/bin` and `/settings/connectors` are not linked from any screen; Google sign-in has no UI (FR-001). `CurrencyPicker` only emits on mouse selection (typed `EUR` + Tab saves the old currency) and has no keyboard or ARIA path; `Dialog` has no Escape, focus management or accessible name; `YearBars` puts `role="img"` over buttons. `ForecastTile`/`MonthCompare` render nothing on error; `PanelState.vue`/`toPanelErrorKind` — the only code producing the FR-019 offline/server/connector copy — is dead. Delete, restore and category-delete have no catch, no confirm and no undo despite `expenses.undo` existing. The date default uses UTC (`toISOString().slice(0,10)`) and `formatDate` parses `y-m-d` as UTC then formats local — off by a day in negative offsets. Month/year switching has no request sequencing (stale-response race). `ImportView` prints raw minor units; `MonthCompare` prints category UUIDs; `BinView` is silently scoped to the last-loaded month. `toApiError` labels a 502 HTML page `validation_failed`. `packages/ui` has no tests despite CLAUDE.md listing it in the unit tier. `OnboardingView` has no error path or busy guard (double-clicking Next skips a step).

**Connectors, tests, CI.** No fetch timeouts; unbounded `Retry-After`. Frankfurter treats 5xx as `unsupported` (permanently pending) and the retry job is a stub. `FakeNotion` returns archived pages that real Notion excludes and `diff()` ignores `archived`. e2e-ci hits live frankfurter (no fake selected in compose), `freezeClock` posts to a mock nothing reads, `TEST_MODE` is documented but unread — add a `RATES_PROVIDER` switch and clock injection, or delete the fixture. `year.spec.ts` uses `toHaveScreenshot` with no committed baselines. `notion.spec.ts` waits 5 minutes inside a 30 s test timeout and its env var is never mapped. `deploy-fly.yml` promotes to production from any `v0.*` tag with no `environment:` protection, and its smoke logs in as a seeded user that has no credential row. `deploy-cf.yml` runs the `ci` project (needs Mailpit and mocks) against a deployed Pages preview. All previews share one `PREVIEW_DATABASE_URL` and run migrations on boot. `hello.spec.ts` still expects "Hello from Desk" at `/`.
